## ✨ Overview

**AI Codebase Analyzer** clones any public GitHub repository, breaks it into semantically meaningful chunks, embeds them into a vector index, and lets you ask natural-language questions about the codebase — answered with real, retrieved source snippets instead of guesses.

Point it at a repo. Ask *"How does routing work?"* or *"Where is authentication handled?"* Get grounded answers backed by the actual code.

Everything runs on your own machine. The only external service is the **Groq API** for answer generation, which has a generous free tier.

---

## 🚀 Features

- 🔍 **Semantic code search** — FAISS-powered vector similarity over embedded source chunks
- 💬 **Grounded Q&A** — Answers generated by Groq's Llama 3.3 70B, backed by retrieved code
- 📚 **Handles large repositories** — no chunk limits, shallow cloning, and dependency folders skipped automatically
- ⚡ **Instant re-analysis** — indexes are cached to disk, so revisiting a repo skips embedding entirely
- 📊 **Repository insights** — file counts, chunk counts, and detected languages
- 🕸️ **Python import graph** — dependency mapping across modules
- 🎨 **Modern, animated UI** — Next.js frontend with glassmorphism and smooth motion
- ⚡ **One command to run** — `./run.sh` handles everything

## 🏗️ How it works

```
┌─────────────────────────┐                       ┌──────────────────────────┐
│   Next.js Frontend        │  ───── HTTP ─────▶   │   FastAPI Backend          │
│   localhost:3000          │                      │   localhost:8000           │
└─────────────────────────┘                      │                            │
                                                    │   1. Clone repository     │
                                                    │   2. Chunk source files   │
                                                    │   3. Embed (MiniLM 384-d) │
                                                    │   4. Index with FAISS     │
                                                    │   5. Retrieve + Ask Groq  │
                                                    └──────────────────────────┘
```

Each analysis gets its own `session_id`, so indexes never collide and you can analyze a new repo without disturbing the last one.

## 🖥️ Running it locally

### Prerequisites

- **Python 3.9+** and **Node.js 18+**
- **Git**
- A free **Groq API key** → [console.groq.com/keys](https://console.groq.com/keys)

### Quick start

```bash
git clone https://github.com/Yadu080/AI-Codebase-Analyzer.git
cd AI-Codebase-Analyzer
./run.sh
```

The first run creates `.env` and stops so you can add your key:

```bash
GROQ_API_KEY=gsk_your_actual_key_here
```

Then run it again:

```bash
./run.sh
```

That's it. `run.sh` will:
- create an isolated `venv` (safe even if you use conda)
- install backend + frontend dependencies on first run
- free ports 8000/3000 if something is already using them
- start the API and the UI together

Open **http://localhost:3000** 🎉

> **First analysis is slower** — SentenceTransformers downloads the embedding model (~90MB) once, then caches it.

## ⚡ Speed & large repositories

By default there are **no limits** — the whole repository gets indexed. Several things keep that fast:

- **Disk-cached indexes** — the first analysis of a repo builds and saves its index; every analysis after that loads it back in about a second, with no re-embedding. The cache is keyed by the repo's commit, so a new commit rebuilds automatically.
- **Clones are reused** — the same repo isn't downloaded twice.
- **Model warm-up at startup** — the embedding model loads in the background as the server boots, so your first analysis isn't waiting on it.
- **Shallow cloning** (`--depth 1`) fetches only the current snapshot, not the entire git history.
- **Dependency folders are skipped** — `node_modules`, `venv`, `dist`, `build`, `__pycache__`, and friends never reach the index, so results stay relevant and indexing stays fast.
- **Progress is logged** to the backend terminal, with a progress bar during embedding.

The first analysis of a large repository still has to embed everything and can take several minutes — watch the backend terminal to follow along. After that it's near-instant.

To force a fresh clone and re-index, send `"refresh": true` to `/analyze`, or delete the `data/` folder.

> **Tip:** `npm run dev` compiles pages on demand. For the snappiest UI, run the frontend in production mode instead: `cd web && npm run build && npm start`.

If you ever want to bound a run, set any of these in `.env`:

| Variable | Default | Purpose |
|---|---|---|
| `MAX_CHUNKS` | `0` (no limit) | Stop after this many chunks |
| `MAX_SOURCE_CHARS` | `0` (no limit) | Stop reading after this many characters |
| `MAX_SESSIONS` | `3` | How many analyzed repos stay in memory |
| `CLONE_TIMEOUT_SECONDS` | `600` | Give up on a slow clone |
| `EMBEDDING_BATCH_SIZE` | `64` | Larger = faster but more memory |
| `USE_INDEX_CACHE` | `1` | Set to `0` to disable the disk cache |

## 📡 API Reference

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/health` | Service status + active session count |
| `POST` | `/analyze` | Clone and index a repository → returns a `session_id` |
| `POST` | `/ask` | Ask a question for a given `session_id` |
| `POST` | `/architecture` | Python import graph for a given `session_id` |

Interactive docs at **http://127.0.0.1:8000/docs**

## ⚠️ Notes

- The vector index lives in memory — analyzing again after a restart re-indexes the repo
- Supported source files: `.py`, `.js`, `.ts`, `.java`, `.cpp`, `.c`
- Only public GitHub repositories (`https://github.com/<owner>/<repo>`) are accepted
